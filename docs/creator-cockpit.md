# Creator Cockpit 使用与架构

## 产品边界

融合版把工作区分为三个一级入口：

- 「会话」保留 Harness 原生会话、Agent、工具卡片和详情面板。
- 「内容」保留 Oil Creator 的选题、脚本、录制、剪辑、字幕、封面、文章和发布流程。
- 「运营」负责灵感、下一步、目标、评分、复盘和经验沉淀。

内容目录仍是正文和制作事实的唯一真源。Cockpit 不保存第二份标题、`topic.md`、`script.md`、`workflow`、`pipeline` 或 `publish`，只用真实 `contentId` 关联运营数据。

## 七个运营页面

运营侧栏的顺序是「灵感库、今日推进、档期规划、内容管线、目标追踪、复盘沉淀、设置与备份」。一级页签旁有灯泡快捷入口，可从会话或内容页直接打开灵感捕捉框。

### 今日推进

汇总今日档期、已逾期事项、T+3 待复盘、当前周期目标和最近灵感。内容阶段实时来自 Oil Creator，推进事项统一来自 Cockpit 档期。

### 灵感库

左侧快速捕捉支持内容类型、分层和标签选择，右侧以编号卡片浏览、筛选和展开操作。内容类型、分层和标签都可以在界面里修改选项。灵感可关联目标；升级为内容时先展示标题与 `topic.md` 预览，再由用户确认，成功后打开同一条真实内容。

升级流程具备进程内单航班锁、revision 校验、library root 包含性检查和 symlink 拒绝。若内容目录已经创建，但 topic 或状态关联失败，界面会返回目录、contentId 和人工恢复提示，不会删除已创建目录，也不会建议盲目重试。

### 档期规划

提供周视图和月视图，可把真实内容的下一步拖入日期，也可建立复盘、直播和自定义事项。所有推进日期只写入一套 Cockpit 档期，今日推进直接读取同一数据，不再维护第二份内容期限。

### 内容管线

实时 join Oil Creator 内容与 Cockpit metadata，按「选题与脚本、录制与制作、待发布、已发布」分列，并支持按标题、下一步、标签搜索和按内容类型筛选。列归属只读 Oil Creator 的真实 workflow，运营侧不能伪造制作阶段。卡片可维护内容类型、层级、优先级、下一步、期限、标签、开头类型、结构类型、关联目标和脚本采用的知识条目。

六维评分为受众、痛点、差异化、素材、开头和结构，每项 0 到 5 分。Host 重算总分并保存 rubric 版本、证据、建议和输入指纹。topic 或 script 改变后，旧评分保留并标记为需要重新评分。

### 目标追踪

支持周期、指标、目标值、关联内容、备注和粉丝快照。每个目标按进度与周期消耗显示「领先、正常、有风险、已达成」或「待补数据」。发布数、播放、点赞和评论从 Oil Creator 汇总；粉丝数来自快照；自定义指标允许人工值。

### 复盘沉淀

已发布内容进入复盘列表，存在发布时间时按 T+3 高亮。页面显示真实播放、点赞和评论，也允许补充收藏、涨粉、点击率、留存率和说明。

AI 只能为真实已发布内容保存复盘草稿。第一次人工确认后才写入 `knowledge/reviews`；规则和模板各自还需要第二次确认。沉淀成功后，Markdown 仍保留在磁盘，同时在 Cockpit v3 state 建立索引。索引条目可启用或停用，并可在内容脚本页按条选择。

### 设置与备份

统一维护发布后几天进入待复盘、内容类型、灵感分层和标签。完整 JSON 备份覆盖灵感、运营元数据、目标、粉丝快照、档期、规则与模板索引和全部选项。恢复时先校验 schema 与 revision，再自动备份当前状态；内容正文、素材和制作产物不在恢复范围内。

## 原版迁移对照

原版基线固定为 `creator-cockpit` 的 `f87820f99e5685adca90ba7cfdc4fde34437c200`。迁移不是另做一套内容系统，而是把运营能力接到 Oil Creator 的真实内容事实：

| 原版能力 | 融合版落点 |
| --- | --- |
| 今日待办、周期目标、待复盘 | 今日推进 |
| 灵感捕捉、筛选、编号选择卡 | 灵感库与全局灯泡入口 |
| 档期、复盘、直播、自定义事项 | 档期规划 |
| 管线、搜索、类型筛选 | 内容管线，阶段读取 Oil Creator |
| 开头、结构、评分 | 内容管线运营元数据与 AI 六维评分 |
| 脚本制作 | Oil Creator 内容创作台，不复制脚本 |
| 目标、粉丝、质量 | 目标追踪 |
| 指标复盘、诊断、规则、模板 | 复盘沉淀与脚本知识桥 |
| 自定义类型、分层、标签、备份恢复 | 设置与备份 |

## 运营知识回到内容创作

内容脚本页会显示当前内容的运营标签、开头、结构和启用知识。用户选择规则或模板后，点击「按运营经验创作」会向当前 Harness 会话提交一条可见指令。Agent 先调用 `cockpit_get_script_context`，再调用 `oil_script_rules`，最后把成稿写入这条内容的真实 `script.md`。运营知识只提供依据，不保存第二份脚本。

## 当前会话 AI 流程

「AI 评分」和「AI 起草复盘」不会启动另一个 CLI，也不读取额外 API Key。按钮通过 `conversation.input.dock` 的当前 session standard kit，把一条完整、可见的用户指令交给当前 Harness 会话。

Host 注册五个严格工具：

- `cockpit_get_script_context`
- `cockpit_get_evaluation_context`
- `cockpit_save_evaluation`
- `cockpit_get_review_context`
- `cockpit_save_review_draft`

context 工具只返回完成任务所需的真实字段。save 工具拒绝未知字段、过期指纹和越界分数；六维总分永远由 Host 计算。运营页面轮询轻量 revision，保存成功后刷新状态。

## 数据与恢复

正式默认数据目录为 `~/.dsh-creator-cockpit-lab`，实验启动则覆盖到仓库内 `.lab/cockpit-data`：

```text
cockpit-data/
├── state.json
├── backups/
├── knowledge/
│   ├── reviews/
│   ├── rules/
│   └── templates/
└── logs/
```

state 当前为 schema v3，新增可定制选项、统一档期、知识索引和脚本策略关系。v0、v1、v2 在读取时迁移到 v3；旧 `dueAt` 会变成一条关联真实内容的档期事项。第一次写回前会按原始 state 创建备份。设置页支持完整 JSON 导出；导入先迁移并校验，再在同一串行写入队列中复核 revision、重建知识 Markdown、备份当前 state，并以当前 revision 递增写入。回滚到只认识旧 schema 的代码前，应先保留 v3 state，再从迁移前备份恢复。其余写入仍使用递增 revision、串行队列、同目录临时文件、`fsync` 和原子 rename。

知识 Markdown 使用 `wx` 创建，不覆盖同名文件。重复请求只有在内容完全一致时才视为幂等；内容不同会明确失败。确认复盘时先完成幂等 Markdown 写入，再更新 state，避免磁盘失败留下「已确认但文件缺失」的半完成状态。

## 隔离启动与回滚

```bash
pnpm build
pnpm lab:setup
pnpm lab:config
pnpm lab:start
```

默认地址是 `http://127.0.0.1:51873`。实验 profile、overlay、内容目录、Cockpit state 和空凭据文件都在 `.lab`。启动器使用额外 patch 禁用已安装 Oil Creator，并加载当前仓库作为唯一同名 bundle。

隔离实验回滚只需停止 `pnpm lab:start`。正式环境使用本地 `link:` 依赖安装本仓库构建产物，回滚时需要在正式 profile 恢复上一个插件依赖并重启 DSH Desktop。Cockpit state 独立于内容目录，回滚插件不会删除运营数据。

## 第一版不做

不迁移旧 IndexedDB，不重做内容制作，不自动发布，不自动把 AI 建议写为正式规则，不做多人云同步，不做桌宠，也不把运营 state 写进内容目录。
